# Lightweight research state

Maintain enough continuity to avoid losing the **why**, not a transaction log. If the current conversation already provides continuity, no extra file is required. For long projects or handoffs, use one short Markdown note in the user's workspace only when requested or clearly useful.

## Suggested note

```markdown
# Research state

**Original goal:** The outcome the researcher actually wants (not the latest favorite tool).
**Current question:** The specific observation/problem under investigation.
**Key evidence:** A few findings, magnitudes, conditions, and links to real data/plots/experiments.
**Working interpretation:** Best provisional explanation; what could change it.
**Next action:** One action and why it is informative; note the researcher's chosen direction.
```

Update after consequential evidence or direction changes, not after every dialogue, parameter tweak, or subagent call. Refer to artifacts by path rather than copying full logs. Keep dormant but potentially interesting leads in one short optional line; do not build an idea tracker without a need.

Periodically distinguish **goal → problem → candidate method → technique**. The researcher may legitimately change goals; if so, update the goal explicitly instead of silently letting a technique become it.
